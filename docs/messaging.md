# Очереди и воркер

Как запустить процессы, описано в [README](../README.md).

## Топология RabbitMQ

Объявляется автоматически при старте: один durable direct exchange `notifications` и три durable очереди `notifications.email`, `notifications.sms`, `notifications.push`. Routing key соответствует каналу.

Формат задания:

```json
{"notification_id": 123, "channel": "sms"}
```

## Relay (публикация outbox)

1. Выбирает неопубликованное событие через `FOR UPDATE SKIP LOCKED`.
2. Переводит уведомление из `created` в `queued`.
3. Отправляет persistent-сообщение с `mandatory=True` и publisher confirms.
4. После подтверждения коммитит статус и `published_at`.

При ошибке публикации транзакция откатывается, следующая попытка выполняется через секунду. Пустой outbox тоже проверяется раз в секунду.

Можно запускать несколько relay одновременно: заблокированные события пропускаются.

## Воркер

Получает по одному сообщению, без автоматического ack.

1. Переход из `created` или `queued` в `sending` выполняется условным `UPDATE`.
2. Транзакция коммитится.
3. Только после коммита отправляется ack.

Переход из `created` допустим на случай, когда публикация дошла до RabbitMQ, а коммит relay не подтвердился. Повторная публикация outbox не откатывает `sending` обратно в `queued`.

### Обработка нештатных случаев

| Ситуация | Поведение |
| --- | --- |
| задача для уведомления в `sending`, `delivered`, `failed` | ack без повторной обработки |
| уведомление отсутствует или канал в БД не совпадает | ack без изменения данных |
| невалидный JSON или неправильный канал в задании | отклоняется без возврата в очередь |
| БД недоступна | пауза секунда, затем nack: задача возвращается в очередь |

## Соединение с брокером

Транспорт использует `aio-pika.connect_robust` для восстановления соединений.
При первоначальном запуске PostgreSQL и RabbitMQ должны быть доступны.

## Гарантии и ограничения

- Потеря подтверждения или сбой до коммита допускают дубли сообщений. Защита от них находится в БД. Гарантии exactly-once для внешней доставки нет.
- Сейчас воркер завершает обработку на статусе `sending` и доставку не выполняет.
- Не реализованы: DLQ, отложенные бизнес-retry, провайдеры, восстановление незавершённой отправки.
